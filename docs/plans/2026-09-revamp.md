# Architecture revamp — review and plan

Date: 2026-09-10, revised the same day after the owner's review. Status: agreed,
execution starts at step 1.

Fallback: tag `v0-keynote` on commit `1c650eb`, the pipeline as it ran on stage.
The tag is created locally in the remote session; the session's git proxy
refuses tag pushes, so the owner pushes it:
`git tag -a v0-keynote 1c650eb -m "Pipeline as run at the keynote" && git push origin v0-keynote`.

This document is the entry point of the revamp. It records what the repository
is today, the decisions taken, and the ordered plan. Each step is one branch,
one pull request and one openspec change; the plan is updated as steps land.

## 1. Findings

The live path is narrow and works: `POST /generate` → `ch7.etat_ch7()` →
`graph.build_graph()` → `chapitre.assembler` → `tts`. Live P90 generation time
is ~6 min for a 25 min stage budget. The problems are structural, not
functional.

**Pipeline.** `orchestrator/graph.py` is 2,135 lines. The graph shape is small
(plan → write ⟲ accumulate → glisse → review → repair → assemble →
poser_gestes → coherence). The complexity lives in `write_node`, which carries
three writing strategies (single call, three segments, bounded beats) plus
best-of-N and the movement method, selected by state flags. `ChapterState` has
30 fields, about half of them experiment switches from sessions 4 to 7.
Preflight and TTS are called from the API and the CLI around the graph, not by
it, although they are full stages of what runs on stage.

**Chapter knowledge is hardcoded, for two chapters.** `STATIONS`,
`_CHUTE_IMPOSEE`, `BANQUE_GLISSEMENT` are dicts keyed `{2, 7}`.
`state.get("chapitre") or 2` appears seven times. `interdits_materiels(texte,
chapitre=2)`. `retrieval.PREAMBULE` is the narrator's voice as a constant.
Chapter 7 is spread across `ch7.py`, two files in `briefs/` parsed by regex on
heading text, and one row of `bible/profond/mouvements-chapitres.md`.
`run_s4.py` inlines the chapter 2 briefs v2–v4 as string constants although its
docstring says they are read from the protocol file.

**Production depends on calibration tooling.** `graph.py` and `gestes.py`
import `lint_style` from `outillage/` through `sys.path.insert` (11 such hacks
in the repo). No `pyproject`, no package, no tests, 37 environment variables as
the only configuration system.

**Artifacts.** 16 run directories, 3 naming schemes (fiche version, chapter,
session/stage), 4 incompatible frontmatter schemas, 21 log files in
`runs-ch7/`. `rapport-etancheite.md` and `rapport-etancheite-s7.md` are
byte-identical. No run directory is referenced by any document. 16 loose
Markdown files at the repository root. No run records the commit it ran on.

**Documentation.** `CLAUDE.md` is 657 lines: ~36 % history, ~26 % decision
records, ~13 % procedures, ~15 % actual agent instructions. 4 of 7 files in
`docs/` are referenced nowhere. `README.md` and `podman-compose.yml` still
describe OpenWebUI, rejected on 2026-08-07. The bible layout described in
`CLAUDE.md` and `README.md` does not match the tree. The pipeline doc is dated
2026-08-10 and predates four graph nodes. `indexer/query_test.py` defaults to
collection `bible`; `index.py` writes `auteur`.

**Language.** Code identifiers are mixed within single modules (`derive_facts`
next to `valider_accumulation`). Directory names are French (`outillage/`,
`journal-des-murs/`). Comments are French and dense (27–34 % of lines) and hold
most of the decision rationale.

## 2. Decisions

1. The keynote has happened; a second run is in ~2.5 months. The API is free
   to change; the owner updates the deck. `POST /generate` requires a payload;
   an empty body is `400`. Artifacts are per run (§6).
2. Experiments stay in the repository, under `experiments/`, as data with a
   manifest per run. Scoring tooling becomes a package module because
   production imports it.
3. Code, comments, docstrings, module and identifier names go to English. This
   reverses the written convention in `CLAUDE.md` and is recorded as an ADR.
   Prompts, bible, briefs, chapter specs and the journal stay French: they are
   the author's material and the model's input.
4. LangGraph stays.
5. Documentation: openspec carries product intent and requirements, ADRs carry
   decisions, three plain docs carry architecture, operations and doctrines
   (§3). No separate PRD. `CLAUDE.md` shrinks to routing and agent
   conventions. Outdated documents are deleted once their surviving content
   is extracted, not archived.
6. Preflight and TTS are pipeline stages with their own spec fields and tests,
   not side utilities of the API.
7. Tests use a fake model with crafted text, not recordings. The protected
   invariant is the set of prompts served, snapshotted from the current code.
8. The revamp is not a quality lever on the prose. It is what makes adding and
   measuring a pipeline module cheap. The 19 min of headroom under the stage
   budget is design space for that, not a target to fill.

## 3. Documentation structure

Four systems, four roles, no overlap:

- **openspec** (`openspec/`, CLI 1.13). `config.yaml` carries the project
  context: what the factory is for, who uses it, the invariants (local only,
  firewall surface/profond, the owner owns canon), conventions. `specs/<capability>/spec.md`: current behaviour as
  requirements and scenarios, one per capability (api, pipeline, chapter-spec,
  retrieval, eval, roleplay, render). `changes/<name>/`: proposals with
  `proposal.md`, `design.md`, `tasks.md`, archived into `specs/` when done.
  One change per step of this plan, then one per experiment. Adopted because
  the deck repository already uses it, so the API contract has one format on
  both sides.
- **ADR** (`docs/adr/NNNN-slug.md`): one decision per file, dated, with
  context, decision, consequences. Append-only. openspec has no durable
  decision log (`design.md` is per change and archived), so ADRs stay.
  Fifteen decisions are extractable from `CLAUDE.md` today (multi-instance
  rejected, three layers, model triage, Ollama out of container, TTS in the
  same venv, per-resource fallback, own chat instead of OpenWebUI, switch after
  second sentence, audio bounded in seconds, Telegram exception, coherence
  protocol, two retrieval strategies, Ollama on loopback, host venv, plus this
  revamp's language, layout and API decisions).
- **Plain docs** (`docs/`): `architecture.md` (one map of the package, the
  graph, the data flows), `runbook.md` (operations, followed under pressure),
  `doctrines.md` (the fourteen doctrines and the falsification rule, one home
  instead of two), `plans/`.
- **Experiments** (`experiments/`): the data. `journal/` with the digest as its
  index, `runs/` with a manifest and a report each, `grids/`.

```
                        render, publish)
                strategies/ (single, segments, beats, best_of)
  chapter_spec/ ChapterSpec model, loader, validation, anti-leak checks
                (code only; the chapter files live in chapters/ at the root)
  prompts/      prompt TEMPLATES as text files (French, .md.j2), no Python
                except one render(); no prompt string lives in node code
  retrieval/    Chroma client, indexer (moved from indexer/), chunking
  eval/         lint (from lint_style), grid, seal test, scorers
  infra/        raw adapters: ollama http, mlx synthesizer, macOS probes,
                telegram, progress sink
  cli.py        factory generate / index / eval / promote / serve
bible/          unchanged, author-owned, French, indexed under the firewall
chapters/       one directory per chapter (spec.yaml + brief.md), author-owned,
                never indexed
experiments/    runs/<date>-<slug>/ (manifest.yaml, report.md, outputs);
                journal/ (README.md = digest); grids/; reports/
docs/           architecture.md, runbook.md, doctrines.md, adr/, plans/
tests/
```

`infra/` holds the calls that touch the machine (HTTP to Ollama, MLX, `vm_stat`,
`sysctl`, `ps`, Telegram). Every one of them sits behind a small interface with
a fake in `tests/`. The nodes that use them (`preflight`, `render`, `write`…)
are pipeline code and are tested against the fakes.

## 5. Chapter spec: what moves to data, what stays in code

Everything that names a chapter's *content* becomes a spec file; everything
that describes *how to run* a strategy stays code and is parametrised by the
spec.

`chapters/07-anniversaire/spec.yaml` (fields derived from what is hardcoded
today in `ch7.py`, `graph.py`, `gestes.py`, `run_s4.py`, `chapitre.py`,
`tts.py`):

```yaml
chapter: 7
slug: anniversaire
narrator: judith
calendar: {weekday: Samedi, number: 14, weather: "Beau temps"}
verdict: anniversaire                 # splice marker for the accumulation
active_objects: "les photos, la playlist, ..."
reserved_objects_scope: 7             # material interdicts (lint) scope
stations: [...]                       # today STATIONS[7]
accumulation_fall: "la playlist qui tourne encore"   # today _CHUTE_IMPOSEE[7]
drift_bank: {approaches: [...], facts: [...]}        # today BANQUE_GLISSEMENT[7]
movement:                             # today one row of mouvements-chapitres.md
  - {entry: 1, text: "..."}
  - {entry: 2, text: "..."}
assembly: {switch_on_second_header: true, audio_until: "Constat : anniversaire."}
render: {audio_seconds: 165, voice: judith, words_per_minute: 177}
entries:
  - weekday: Samedi
    number: 14
    words: [25, 60]
    sentences_max: 2
    citation: ""
    gestures: false
    strategy: single
    best_of: {n: 3, criterion: erasure-anniversary}
    material: [...]
    vetos: "..."
    form: {accumulation: absent, verdict: absent}
  - weekday: Samedi
    number: 14
    words: [300, 400]
    citation: "« Neuf ans aujourd'hui ... »"
    gestures: true
    fall: "Constat : anniversaire."
    strategy: beats
    beats:

      - {name: découverte, num_predict: 240, sentences_max: 5, instruction: "..."}
      - {name: doute, num_predict: 150, sentences_max: 4, instruction: "..."}
    trajectory: [...]
    material: [...]
    vetos_served: "..."               # world language, the only vetos the model sees
    drift: {text: "...", position: "..."}
```

`brief.md` next to it holds the human-facing brief (what is projected on stage)
and implementer notes that are never served. The loader applies the anti-leak
assertions that `ch7.brief_chapitre_7()` applies today (no bible filename in
served text, no workshop vocabulary).

Stays in code: the strategies (`single`, `segments`, `beats`, `best_of`), the
composition primitives (header, prefixing, reattach, sentence bounding), the
validators (parametrised by spec values, never by chapter number), the
scorers. Scorers are a registry keyed by name (`erasure-anniversary`); a
criterion's lexical lists live in the spec, the scoring mechanism in code.

Chapter 2 gets a spec written from the constants in `run_s4.py` and `graph.py`
(brief v4, anchor, stations, fall, bank). Chapters 1, 3–6, 8–11 get a spec
file each as the author writes their movements; an entry with no strategy
falls back to `single`.

The chapter spec directory is outside `bible/`; the indexer never reads it,
and the seal test gains a control that no `chapters/` content is in any
collection.

## 6. Runs, narrative state, API

**Runs.** A run is `(chapter spec, seed, config overrides, commit)`. It gets an
id, a directory under `experiments/runs/<date>-<slug>/` with `manifest.yaml`
(id, chapter, seed, commit, resolved config, model tags, timings, two clocks),
the assembled chapter, the served prompts, the WAV, the lint grid line and an
optional `report.md`. The run registry is the on-disk directory; the API reads
it.

**API.**

```
POST /generate              {chapter, seed?, overrides?} → 202 {run_id}; 400 without body
GET  /runs                  list, newest first
GET  /runs/<id>/status
GET  /runs/<id>/events      SSE, status payload ~1/s, closes on terminal state
GET  /runs/<id>/chapter     text/markdown with both markers; 204 until written
GET  /runs/<id>/audio       audio/wav; 204 until rendered
GET  /runs/<id>/prompts     prompts served to the model, per node and entry
POST /runs/<id>/cancel
GET  /runs/latest/...       alias of the most recent run
POST /chat   GET /characters   GET /sessions   GET /session/<c>/<ts>   (unchanged)
GET  /health
```

`/prompts` exists for the stage (the projected brief and the served prompt must
be the same text) and for the recopy measure of the movement method.

One model in memory at a time: generation is a queue of one worker, and a
`POST` while a run is active queues rather than refuses. The chat route keeps
its `409` during generation, for the reason documented today.

**Narrative state.** Today `build_etat_narratif.py --chapitre N` reads the
author's table (`bible/profond/chronologie-partie-double.md`, the deep column
skipped by design), overwrites section 7 of `bible/fiche-judith.md`, then the
bible is reindexed. Generating chapter N+1 requires that step, and it is not in
the pipeline.

Decision: the narrative state stays derived from the author's table, never
from generated text. Two changes make it batchable:

1. The state becomes a generated file per chapter,
   `bible/generated/narrative-state/ch-NN.md`, indexed with metadata
   `chapter: N`. All chapters are indexed once; retrieval selects by
   `(doc_id, section, chapter)`. No reindex between chapters. The generator
   is the `narrative_state` node, idempotent, first in the graph after
   preflight.
2. Generated chapters are candidates, not canon. `factory promote <run>`
   copies a chapter into `bible/scenes/` after the owner's reading; only
   promoted scenes enter semantic retrieval. Serving previous entries during
   writing stays disabled (measured: the model copies them); promoted scenes
   serve review and coherence.

A chapter's inputs are exactly: its spec, the narrator sheet, the state chunk
for its number, the style contract, promoted scenes. Nothing from an
unpromoted run reaches the next.

## 7. Tests

No tests exist. The refactor moves code proven only by runs, so the tests are
written first (step 2), against the current layout, and carried through the
moves. Nothing requires the owner's machine.

**The fake model.** `llm.chat` and `llm.chat_turns` are replaced by a
dispatcher that recognises the node from the system prompt (plan, write,
accumulate, drift, review, repair, QA facts, QA questions, QA answers, QA
confirm, roleplay, summary) and returns crafted French text from
`tests/fixtures/`. Nominal fixtures are conforming (pass sentence bounds,
validators, scorers, answer format) so the graph takes its nominal path;
failing fixtures exercise continuation, best-of rejection, accumulation
retry, plan refusal, out-of-role relaunch. Retrieval by id is served from the
indexer's own chunker over `bible/` (deterministic, no Chroma); semantic
retrieval returns fixtures.

**Snapshot of served prompts** (`tests/snapshots/`). The graph runs on the
chapter 7 spec and on the chapter 2 stage S7 configuration, fixed seed, fake
model. Every prompt served and the assembled chapter are written as golden
files from the current code. Steps 4 and 5 must reproduce them byte for
byte. This is the invariant of the refactor: the wording, order and served
sections calibrated over seven sessions do not move.

**Unit tests** (`tests/unit/`), pure functions, no fakes needed:

- `style`: `sentence_ends`, `ends_mid_sentence`, `trim_to_sentence`, `delint`.
- `chapitre`: `inserer_bascule` (sentence mode, second-header mode, short
  text fallback), `extrait_audio` (word bound, fall), `assembler` (both
  markers always present).
- `graph` helpers: `entete`, `separer_meteo`, `_recoller`,
  `_retirer_reprise_approximative`, `_borner_en_phrases`, `_nettoyer_segment`,
  `_scorer_beat`, `_scorer_entree1`, `_retamponner`.
- `gestes`: `composer_glissement`, `position_*`, `valider_accumulation`,
  `approche_valide`, `passage_valide`, `assembler`, `tirer_approche` (seeded,
  no repeat within a chapter).
- `lint_style.analyse` and `controles_chapitre`: snapshot over the 32 journal
  files and the `runs-ch7` files, the falsification baseline in both
  directions.
- `qa` parsers: `_ANSWER_RE`, `_sourced`, `_parse_questions`.
- `notify._assainir`: the three real cases documented in `CLAUDE.md`.
- `roleplay`: `hors_role`, `_nettoyer`, session file round trip.
- `ch7` parsers: `brief_chapitre_7`, `brief_entree2_v2`, `beats_chapitre_7`,
  `mouvement`, anti-leak assertion. In step 5 the same tests assert the new
  loader returns the same values.
- `indexer` chunking: sections, the three firewall barriers, metadata
  whitelist, name translation.

**Stage tests with fakes** (`tests/stages/`):

- `preflight`: the gate logic against fabricated probe results (disk, swap
  total and free, pageout rate, memory pressure, noisy daemons, loaded models,
  generation probe): every blocking rule fires on its known case and stays
  quiet on a healthy machine; `chrono` mode differences; warnings versus
  errors.
- `render` (TTS): `segmenter`, WAV assembly with a fake synthesizer returning
  silence of a chosen duration, the pause between segments, the
  duration-versus-target check and its note, the per-resource fallback (a
  synthesizer failure leaves the chapter served and the audio absent).
- `api`: server in-process, pipeline replaced by a fake worker: `400` without
  payload, `202` with `run_id`, queueing, per-run `204` before artifacts
  exist, `409` on chat during generation, the five known path-traversal cases
  rejected `400`, slides traversal rejected `403`, SSE terminal event.
- `retrieval`: system prompt assembly with and without RAG, sections served
  per role, example lines stripped.

**Not covered**: the real MLX synthesis and the real macOS probes. Both are one
call each behind an interface. `factory doctor` runs them on the owner's
machine and prints the result; that is the runbook's first step, not a test.

**Lifecycle of the safety net.** The suite of step 2 is written against a
layout that steps 4 to 6 dismantle. It is not kept as-is. Two kinds of tests:

- *Scaffolding*, deleted or rewritten as the steps land: the path wiring and
  four-module patching in `conftest.py` (step 4), the scenario state builders
  reproducing `ch7.py` and `run_s4.py` (step 5, the golden files stay), the
  chapter-7 regex parser tests (step 5), the keynote-contract API tests
  (step 6), the strict xfail (flips or is deleted with its fix).
- *Keepers*, moved and renamed with the code they test, assertions intact:
  assembly markers, header composition, gesture validators and positions, beat
  scorers, QA parsers, notifier sanitiser, out-of-role guard, indexer
  firewall, preflight gate, render fallback, retrieval sections per role.

Every step's `tasks.md` states which tests it moved, rewrote or deleted. Step
7's exit criterion includes: no test references the old layout, no `sys.path`
wiring in `conftest.py`, no xfail, no test file whose subject no longer exists.

## 9. Findings of the safety net (step 2)

Writing the tests against the current code surfaced three things. None is
fixed in step 2, which changes no behaviour; each has a home.

- **Accumulation validator, last attempt.** The word/comma tolerance on the
  last attempt returned before the language check: a SHORT English
  accumulation was accepted on the last try. Recorded as a strict expected
  failure in `tests/unit/test_gestes.py`; **fixed at step 5** (the language
  check now runs first), the test flipped.
- **Header counts as two sentences.** In sentence mode the audio switch on a
  chapter whose first entry is one sentence lands right after the dated header
  (the header's two periods are two sentences). Harmless for chapter 7 (second
  header mode) and chapter 2 (long entries). Documented in
  `tests/unit/test_chapitre.py`; the switch rule becomes a spec field at step 5.
- **Name binding.** Every module does `from llm import chat`, so the model
  client cannot be swapped in one place; the tests patch four modules. The
  package step introduces one client object injected once.
