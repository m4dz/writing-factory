# Architecture revamp — review and plan

Date: 2026-09-10. Status: agreed with the owner, execution starts at step 1.
Fallback: tag `v0-keynote` (commit `1c650eb`) is the pipeline as it ran on stage.
The tag is created locally in the remote session; the session's git proxy
refuses tag pushes, so the owner pushes it: `git tag -a v0-keynote 1c650eb -m
"Pipeline as run at the keynote" && git push origin v0-keynote`.

This document is the entry point of the revamp. It records what the repository
is today, the decisions taken, and the ordered plan. Each step below becomes one
branch and one pull request; the plan is updated as steps land.

## 1. Findings

The live path is narrow and works: `POST /generate` → `ch7.etat_ch7()` →
`graph.build_graph()` → `chapitre.assembler` → `tts`. Live P90 generation time
is ~6 min for a 25 min stage budget. The problems are structural, not
functional.

**Pipeline.** `orchestrator/graph.py` is 2,135 lines. The graph shape is small
(plan → write ⟲ accumulate → glisse → review → repair → assemble →
poser_gestes → coherence). The complexity lives in `write_node`, which carries
three writing strategies (single call, three segments, bounded beats) plus
best-of-N and the movement method, selected by state flags. `ChapterState` has
30 fields, about half of them experiment switches from sessions 4 to 7.

**Chapter knowledge is hardcoded, for two chapters.** `STATIONS`,
`_CHUTE_IMPOSEE`, `BANQUE_GLISSEMENT` are dicts keyed `{2, 7}`.
`state.get("chapitre") or 2` appears seven times. `interdits_materiels(texte,
chapitre=2)`. `retrieval.PREAMBULE` is the narrator's voice as a constant.
Chapter 7 is spread across `ch7.py`, two files in `briefs/` parsed by regex on
heading text, and one row of `bible/profond/mouvements-chapitres.md`.
`run_s4.py` inlines the chapter 2 briefs v2–v4 as string constants although its
docstring says they are read from the protocol file.

**Production depends on calibration tooling.** `graph.py` and `gestes.py`
import `lint_style` from `outillage/` through `sys.path.insert` (11 such hacks
in the repo). No `pyproject`, no package, no tests, 37 environment variables as
the only configuration system.

**Artifacts.** 16 run directories, 3 naming schemes (fiche version, chapter,
session/stage), 4 incompatible frontmatter schemas, 21 log files in
`runs-ch7/`. `rapport-etancheite.md` and `rapport-etancheite-s7.md` are
byte-identical. No run directory is referenced by any document. 16 loose
Markdown files at the repository root. No run records the commit it ran on.

**Documentation.** `CLAUDE.md` is 657 lines: ~36 % history, ~26 % decision
records, ~13 % procedures, ~15 % actual agent instructions. 4 of 7 files in
`docs/` are referenced nowhere. `README.md` and `podman-compose.yml` still
describe OpenWebUI, rejected on 2026-08-07. The bible layout described in
`CLAUDE.md` and `README.md` does not match the tree. The pipeline doc is dated
2026-08-10 and predates four graph nodes. `indexer/query_test.py` defaults to
collection `bible`; `index.py` writes `auteur`.

**Language.** Code identifiers are mixed within single modules (`derive_facts`
next to `valider_accumulation`). Directory names are French (`outillage/`,
`journal-des-murs/`). Comments are French and dense (27–34 % of lines) and hold
most of the decision rationale.

## 2. Decisions

1. The keynote has happened; a second run is in ~2.5 months. The deck contract
   (`docs/contrat-api-pour-le-deck.md`, openspec change
   `remote-integration-contract` in the talk repo) remains binding: an empty
   `POST /generate` body keeps producing the default chapter. Payloads are
   additive.
2. Experiments stay in the repository, under `experiments/`, as data with a
   manifest per run. Scoring tooling becomes a package module because
   production imports it.
3. Code, comments, docstrings, module and identifier names go to English. This
   reverses the written convention in `CLAUDE.md` and is recorded as an ADR.
   Prompts, bible, briefs, chapter specs and the journal stay French: they are
   the author's material and the model's input.
4. LangGraph stays.
5. Documentation moves to: `README.md` (routing), `docs/prd.md`,
   `docs/architecture.md`, `docs/adr/`, `docs/runbook.md`, `docs/api.md`,
   `docs/experiments.md`, `docs/doctrines.md`. openspec is adopted for change
   proposals (see §3). `CLAUDE.md` shrinks to routing and agent conventions.
6. The revamp is not a quality lever on the prose. It is what makes adding and
   measuring a pipeline module cheap. The 19 min of headroom under the stage
   budget is design space for that, not a target to fill.

## 3. Documentation structure: PRD, ADR, openspec

Three systems, three roles, no overlap:

- **PRD** (`docs/prd.md`): what the factory is for, who uses it, the invariants
  (local only, firewall surface/profond, human owns canon). Stable, rewritten
  rarely.
- **ADR** (`docs/adr/NNNN-slug.md`): one decision per file, dated, with
  context, decision, consequences. Append-only. Fifteen decisions are
  extractable from `CLAUDE.md` today (multi-instance rejected, three layers,
  model triage, Ollama out of container, TTS in the same venv, per-resource
  fallback, own chat instead of OpenWebUI, switch after second sentence, audio
  bounded in seconds, Telegram exception, coherence protocol, two retrieval
  strategies, Ollama on loopback, host venv, plus this revamp's language and
  layout decisions).
- **openspec** (`openspec/specs/` for current behaviour per capability,
  `openspec/changes/<name>/` for proposals with proposal, design, tasks): one
  change per step of this plan. Adopted because the deck already freezes the
  API contract there, so the contract lives in one format on both sides.
- **Runbook** (`docs/runbook.md`): operations only, followed under pressure.
- **Doctrines** (`docs/doctrines.md`): the fourteen doctrines and the
  falsification rule, currently duplicated between `CLAUDE.md` and
  `docs/passation-generale.md`. One home.

## 5. Chapter spec: what moves to data, what stays in code

The question is where chapter logic lives once the API receives only an
identifier. Answer: everything that names a chapter's *content* becomes a spec
file; everything that describes *how to run* a strategy stays code and is
parametrised by the spec.

`chapters/07-anniversaire/spec.yaml` (fields derived from what is hardcoded
today in `ch7.py`, `graph.py`, `gestes.py`, `run_s4.py`):

```yaml
chapter: 7
slug: anniversaire
narrator: judith
calendar: {weekday: Samedi, number: 14, weather: "Beau temps"}
verdict: anniversaire                 # splice marker for the accumulation
active_objects: "les photos, la playlist, ..."
reserved_objects_scope: 7             # material interdicts (lint) scope
stations: [...]                       # today STATIONS[7]
accumulation_fall: "la playlist qui tourne encore"   # today _CHUTE_IMPOSEE[7]
glissement_bank: {approaches: [...], facts: [...]}   # today BANQUE_GLISSEMENT[7]
movement:                             # today one row of mouvements-chapitres.md
  - entry: 1
    text: "..."
  - entry: 2
    text: "..."
assembly: {switch_on_second_header: true, audio_until: "Constat : anniversaire."}
entries:
  - weekday: Samedi
    number: 14
    words: [25, 60]
    sentences_max: 2
    citation: ""
    gestures: false
    strategy: single
    best_of: {n: 3, criterion: erasure-anniversary}
    material: [...]
    vetos: "..."
    form: {accumulation: absent, verdict: absent}
  - weekday: Samedi
    number: 14
    words: [300, 400]
    citation: "« Neuf ans aujourd'hui ... »"
    gestures: true
    fall: "Constat : anniversaire."
    strategy: beats
    beats:
      - {name: relève, num_predict: 150, sentences_max: 4, instruction: "..."}
      - {name: découverte, num_predict: 240, sentences_max: 5, instruction: "..."}
      - {name: doute, num_predict: 150, sentences_max: 4, instruction: "..."}
    trajectory: [...]
    material: [...]
    vetos_served: "..."               # world language, the only vetos the model sees
    glissement: {text: "...", position: "..."}
```

`brief.md` next to it holds the human-facing brief (what is projected on stage)
and implementer notes that are never served. The loader applies the anti-leak
assertions that `ch7.brief_chapitre_7()` applies today (no bible filename in
served text, no workshop vocabulary).

Stays in code: the strategies (`single`, `segments`, `beats`, `best_of`), the
composition primitives (`header`, prefixing, `reattach`, sentence bounding),
the validators (parametrised by spec values, never by chapter number), the
scorers. Scorers are a registry keyed by name (`erasure-anniversary`); a
criterion's lexical lists live in the spec, the scoring mechanism in code.

Chapter 2 gets a spec written from the constants in `run_s4.py` and `graph.py`
(brief v4, anchor, stations, fall, bank). Chapters 1, 3–6, 8–11 get a spec
file each as the author writes their movements; an entry with no strategy
falls back to `single`.

The chapter spec directory is outside `bible/`; the indexer never reads it,
and the seal test (`etancheite`) gains a control that no `chapters/` content
is in any collection.

## 6. Narrative state between chapters

Today: `build_etat_narratif.py --chapitre N` reads the author's table
(`bible/profond/chronologie-partie-double.md`, one row per chapter, the deep
column skipped by design), writes section 7 of `bible/fiche-judith.md`, then
the bible is reindexed. `write_node` retrieves that chunk deterministically by
id. Generating chapter N+1 therefore requires a regenerate-and-reindex step
that is not in the pipeline.

Decision: the narrative state stays derived from the author's table, never
from the generated text. The model reads truth stored outside it, and the
owner owns canon. Two changes make it batchable:

1. The state chunk becomes a generated file per chapter,
   `bible/generated/narrative-state/ch-NN.md`, indexed with metadata
   `chapter: N`. All chapters are indexed once; retrieval selects by
   `(doc_id, section, chapter)`. No reindex between chapters. The generator
   moves to `factory.spec` and runs as the first pipeline stage (idempotent).
2. Generated chapters are candidates, not canon. `factory promote <run>`
   copies a chapter into `bible/scenes/` after the owner's reading; only
   promoted scenes enter semantic retrieval. Serving previous entries during
   writing stays disabled (`include_scenes=False`, measured: the model copies
   them); promoted scenes serve review and coherence.

So a chapter's inputs are exactly: its spec, the narrator sheet, the state
chunk for its number, the style contract, and promoted scenes. Nothing from
an unpromoted run leaks into the next.

## 7. Tests

No tests exist. The refactor moves code proven only by runs, so the tests are
written before anything moves (step 2), against the current module layout,
and carried through the moves.

**Golden unit tests, no model, no network** (`tests/unit/`):

- `style`: `sentence_ends`, `ends_mid_sentence`, `trim_to_sentence`,
  `delint` (French guard, franglais map, glued participles, garbage tokens).
- `chapitre`: `inserer_bascule` (sentence mode, second-header mode, short
  text fallback), `extrait_audio` (word bound, `jusqu_a` fall), `assembler`
  (both markers always present).
- `graph` pure helpers: `entete`, `separer_meteo`, `_recoller`,
  `_retirer_reprise_approximative`, `_borner_en_phrases`,
  `_nettoyer_segment`, `_scorer_beat`, `_scorer_entree1`, `_retamponner`.
- `gestes`: `composer_glissement`, `position_accumulation`,
  `position_glissement`, `position_frontiere`, `valider_accumulation`,
  `approche_valide`, `passage_valide`, `assembler`, `tirer_approche`
  (seeded determinism, no repeat within a chapter).
- `lint_style.analyse` and `controles_chapitre`: snapshot of the current
  output on the 32 files of `journal-des-murs/` and the 4 `runs-ch7` files.
  The snapshot is the falsification baseline, both directions.
- `qa` parsers: `_ANSWER_RE`, `_sourced` (citation must be in the scene),
  `_parse_questions`.
- `notify._assainir`: the three real cases documented in `CLAUDE.md`.
- `roleplay`: `hors_role`, `_nettoyer`, session file read/write round trip.
- `ch7` parsers: `brief_chapitre_7`, `brief_entree2_v2`, `beats_chapitre_7`,
  `mouvement`, anti-leak assertion. In step 5 the same tests assert the new
  loader returns the same values.
- `preflight` parsers on recorded `vm_stat`, `sysctl`, `ps` outputs (the
  system calls are stubbed; the macOS adapter is not tested here).
- `api` handlers with the server started in-process and the job stubbed:
  route table, `202` idempotence, `204` when artifacts are absent, `409`
  chat during generation, the five known path-traversal cases rejected
  `400`, slides path traversal rejected `403`.
- `indexer` chunking: sections, firewall barriers (excluded paths, `[SURFACE]`
  only, numbered sections only), metadata whitelist, name translation.

**Replay tests, fake model** (`tests/replay/`): `llm.chat` and `llm.chat_turns`
are replaced by a recorder/replayer keyed by `(model, sha256(system + user))`.
Retrieval by id is served from the indexer's own chunker over `bible/`
(deterministic, no Chroma); semantic retrieval returns fixtures. The full
graph runs on the chapter 7 spec at a fixed seed and the test asserts
(a) every served prompt equals the recording, (b) the assembled chapter equals
the recording. This is the invariant that steps 4 and 5 must not break.

The recording must be captured once on the owner's machine (Ollama), on the
current code, before step 4: `factory record --chapter 7 --seed <n>` writes
`tests/replay/fixtures/ch7-seed-<n>/`. The remote session cannot run models.

**Not covered**: TTS rendering (MLX, macOS only; `segmenter` is unit-tested),
preflight system calls, live Chroma. Documented as such in
`docs/experiments.md`.

behaviour changes before step 5, and step 5 proves it changed nothing.
